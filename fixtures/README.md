# fixtures/ — v1 API 응답 사본 (로컬 개발용)

> 🔴 **계약의 정본은 `CONTRACT.md` §v1 이다. 이 폴더는 사본이다.**
> **손으로 고치지 말 것.** 고쳐야 할 것 같으면 계약이 틀린 것이고, 그건 기획에 올린다.

## 왜 있나

분리 후 프론트 저장소는 **네트워크 없이도 빌드할 수 있어야** 한다.
백엔드가 발행하기를 기다리지 않고 화면을 짜기 위한 설비이며, 이전용 임시방편이 아니다.

## 규칙 — 받아 적는 것이지 손으로 쓰는 것이 아니다

| | |
|---|---|
| 만드는 법 | `python fixtures/capture.py <커밋 또는 URL>` — **한 단계** |
| 계약이 바뀌면 | **다시 받아 적는다.** 손으로 맞추는 순간 「계약이 정본」이 깨진다 |
| 배포에 쓰나 | **안 쓴다.** 배포는 언제나 실물 API를 본다 |

낡아도 **배포는 안 틀리고 로컬만 낡는다.** 모든 응답에 `generated`가 있어 낡으면 눈에 보인다.

JSON 에는 주석을 못 다니 이 경고가 파일 안에 못 들어간다 — 그래서 여기 둔다.
`capture.py` 가 받아 적을 때마다 아래 출처를 다시 쓴다.

## 지금 사본의 출처

```
출처    https://api.galmal.kr/v1  (라이브)
발행    generated 2026-09-30T04:21:43+09:00 · preserved false
받은 것 51개 — meta · deals · vocab · routes/index · routes/{code} 47 · 딜 140 · 링크 700
확인    capture.py 가 받아 적은 직후 빌드와 같은 스냅숏 규칙으로 검사 — 한 발행분 ✅
```

🔴 **이 사본에는 「얇은 노선」이 들어 있다.** 수집 14일 미만인 딜이 **49건**, 14일 이상이 **91건**이다.
얇은 쪽(sitemap 제외 · `수집 N일째` 머리말 · 「평소 시세」 칸 없음)은 두꺼운 노선만 있는 사본으로는
**실데이터로 한 번도 안 지나간다.** 노선이 36 → 43 → 47 로 늘어 온 동안 계속 둘 다 있었다.
다시 받을 때 **두 갈래가 다 남아 있는지** 본다(`tests/test_route.py` `test_fixture_has_both_kinds`).

🔴 **신기록 딜은 「1건 이상」만 요구한다**(2026-09-30 에 바뀌었다 — 기획 결정, B79).
`low`·`obs_days≥14`·낙폭 5%+ 를 넘는 딜이 지금 사본에 **1건**(그중 도장 15%+ 와 겹치는 것 1건)이다.

예전엔 **「도장 없는 신기록」도 1건 이상** 있어야 했다(카드에 신기록이 뜨는 걸 실데이터로 재려고).
그런데 그 조합이 **사흘에 하루쯤만 존재한다** — 실측: 09-28 신기록 3(가려짐 2·카드 1) · 09-29 2(2·0) ·
09-30 1(1·0). 이유는 구조적이다: 신기록은 「14일 최저가를 5% 밑돌았다」, 도장은 「중위가 대비 15% 할인」이라
**새 최저가를 쓰면 중위가 대비도 웬만하면 15%를 넘는다.** 두 조건이 같이 움직인다.
그래서 **사본을 갱신할 수 없었다** — 이틀 연속 받고 되돌렸다.

지금 규칙 — **매일 참일 수 있는 조건만 실데이터에 건다.** 드문 조합은 `tests/test_record.py`
`SyntheticCardTest` 가 **합성 데이터**로 네 경우를 다 본다(이름에 🧪 를 밝혀 둔다).
검사를 끈 게 아니라 **실데이터로 지킬 것과 합성으로 지킬 것을 가른 것**이다.

🔴 **이 사본에는 `links[].pax_url` 이 있다**(2026-09-22 계약 추가, 백엔드 `36c6f38`). 링크 700개 전부
치환 가능하고 「인원 못 받음(`null`)」은 0건이다. 빌드가 **쓰기 전에** `{n}`→`1` 이 `url` 과 바이트 동일한지
검사한다(`site/pax.py`) — 어긋나면 배포되지 않는다. 다시 받을 때 `null` 이 섞여 들어오면 그건 정상이다
(그 예약처가 인원을 못 받는다는 뜻이고 화면에 `1인 기준으로 열려요` 가 붙는다).

🔴 **이 사본에는 `deals[].oa`(실제 출발 공항)와 `vocab.airport_name` 이 있다**(2026-09-22 계약 추가,
백엔드 `3ab6067`, 라이브 반영은 09-23~). `SEL` 은 가상 허브라 **인천과 김포가 섞여 있다** —
지금 사본은 `SEL` 딜 75건 중 **ICN 62 · GMP 13** 이다.

다시 받을 때 **김포가 0건이 되면 검사가 눈을 감는다**: 「가상 허브를 진짜 공항으로 푼다」는 이 기능의
이유 자체가 인천/김포가 **섞여 있을 때만** 실데이터로 지나간다. `tests/test_origin.py`
`test_fixture_has_a_split_hub` 가 그걸 본다 — 얇은/두꺼운 노선, 신기록 두 갈래와 같은 이유다.

**이 사본은 한 발행분이다.** 그래서 픽스처 빌드도 라이브 빌드와 **같은 검사**를 받는다 —
예전엔 `--no-snapshot-check` 로 검사를 껐다.
